### Задание hw1_crawler
- **Цель**: скачать не менее 100 HTML‑страниц на одном языке и сохранить их вместе с разметкой, 
сформировать файл со списком всех скачанных страниц.
- **Реализация**: написан простой веб‑краулер на Java, который:
  - читает стартовые ссылки из `seeds.txt`,
  - обходит только допустимые хосты,
  - фильтрует ресурсы по типу содержимого и объёму текста,
  - сохраняет страницы в `hw1_crawler/output/pages` и записывает пары `имя файла — URL` в 
`hw1_crawler/output/index.txt`.
- **Дополнительно**: реализована фильтрация технических и редактируемых страниц (например, `action=edit`, 
`redlink=1` у Википедии), чтобы в выборку попадали только полноценные текстовые страницы.

### Задание hw2_tokenization
- **Цель**: на основе сохранённых HTML‑страниц из `hw1_crawler` получить:
  - список уникальных токенов (слов без дубликатов, чисел, предлогов/союзов и мусорных фрагментов),
  - группы токенов, объединённых по леммам (нормальным формам слов).
- **Реализация**: модуль `hw2_tokenization`:
  - читает HTML‑страницы из `hw1_crawler/output/pages` и извлекает из них основной текст,
  - токенизирует текст на слова, оставляя только русские слова и убирая смешанные/мусорные токены,
  - с помощью библиотеки AOT выполняет морфологический анализ и лемматизацию,
  - фильтрует служебные части речи (предлоги, союзы, частицы и т.п.),
  - формирует два файла: `hw2_tokenization/output/tokens.txt` (уникальные токены) и `hw2_tokenization/output/lemmas.txt` (лемма и её токены в одной строке).

### Задание hw3_inverted_index
- **Цель**: построить инвертированный индекс по документам, полученным на этапе краулинга, и реализовать булев поиск по нему.
- **Реализация**: модуль `hw3_inverted_index`:
  - читает HTML‑страницы из `hw1_crawler/output/pages` и список документов из `hw1_crawler/output/index.txt`,
  - извлекает текст и приводит слова к леммам,
  - строит инвертированный индекс вида `термин -> список документов`,
  - сохраняет индекс в `hw3_inverted_index/output/inverted_index.txt`,
  - поддерживает булевы запросы с операторами `AND`, `OR`, `NOT` и круглыми скобками,
  - принимает поисковый запрос либо из строки запуска, либо из консольного ввода.

### Задание hw4_tf_idf
- **Цель**: для каждого скачанного ранее документа необходимо подсчитать `tf`, `idf` и `tf-idf` как для терминов, так и 
для лемматизированных форм.
- **Реализация**: модуль `hw4_tf_idf` читает HTML-страницы из `hw1_crawler/output/pages`, извлекает текст, нормализует 
токены, лемматизирует их, вычисляет частоты внутри документа и `idf` по всему корпусу, а затем сохраняет результаты в постраничные файлы:
  - `hw4_tf_idf/output/terms/<doc>.txt`
  - `hw4_tf_idf/output/lemmas/<doc>.txt`
- **Формат вывода**: каждая строка имеет вид `<термин или лемма> <idf> <tf-idf>`.

### Задание hw5_search_engine
- **Цель**: разработать поисковую систему на основе векторного поиска по построенному индексу и предоставить для неё web-интерфейс.
- **Реализация**: модуль `hw5_search_engine` представляет собой веб-приложение на сервлетах, которое:
  - читает TF-IDF-векторы документов из `hw4_tf_idf/output/lemmas`,
  - обрабатывает пользовательский запрос,
  - нормализует и лемматизирует термины запроса,
  - вычисляет косинусное сходство между запросом и документами,
  - ранжирует результаты,
  - показывает top 10 результатов через web-страницу.
- **Запуск**: модуль разворачивается как WAR-приложение в Apache Tomcat.
